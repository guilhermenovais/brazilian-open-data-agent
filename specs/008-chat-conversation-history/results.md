## Why the failing turns failed

Diagnosed from each turn's `steps` in the run file:

1. **Abbreviation used as an exact filter (follow-up-metric 0/3, follow-up-reference-02).** The
   agent filters `nome_unidade equals "AEB"` or `nome_acao equals "desenvolvimento do satélite
   Amazônia-1"`, gets 0 rows, and correctly declines. The context turn of `follow-up-metric-01`
   ("Quanto foi pago pela AEB em 2012?") fails the same way, so this is a weakness in how the
   model uses the tools, not in the conversation mechanism. The follow-up did query again
   instead of repeating the earlier answer (v2 rule 14). Possible fixes to evaluate next: have
   the briefing map "AEB" to the full unit name, or have the prompt prefer `contains` for text
   filters. Either change also affects the standalone path, so each needs a measured before/after
   comparison (Principle II).
2. **Mental arithmetic over `query_rows` instead of `aggregate_rows`.** This produced wrong totals
   in `clarification-03` t2, `long-conversation-01` t12/t16, and the web walkthrough (R$ 105.318.565
   for AEB 2011; the correct value is 108.537.469). In each case the rows retrieved were complete;
   only the model's sum was wrong. The grounding screen flagged every one of these figures.
3. **No decline for context-free follow-ups (SC-005, US2-AS2).** On a fresh chat, "e em 2016?" and
   "e o empenhado?" get a guessed subject (an MCTIC/AEB note, a 2009 total) with outcome
   `partial` instead of a vague-question decline. The chat request itself carried
   `history_turns_used = 0`, so no context leaked. The model simply does not decline.
4. **The model rarely asks for clarification.** On "Me fale sobre o orçamento." it summarises
   instead of asking. Per the spec Assumptions, v2 does not change *when* the agent asks. The
   reply turns were still answered from context in 2 of 3 `clarification` conversations.
